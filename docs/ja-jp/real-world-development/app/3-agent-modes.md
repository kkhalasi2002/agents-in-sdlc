プロジェクトに小さな機能を追加しました。より大きな変更には、さらに堅牢なプロセスが必要です。GitHub Copilot app は組織の既存のフローに沿って作業できるため、適切なものを適切な方法で構築できます。このレッスンから数回にわたり、一般的なエージェント主導の開発プロセスを実践します。Issue から新機能を作成し、コードが有効で、機能が期待どおりに動作することを確かめ、最終的にプロジェクトへマージします。

> [!NOTE]
> 機能に関するワークフローでは、同じセッションを続けて使用します。通常は作業対象のファイルごとに異なるセッションや PR を使いますが、ここでは中心となる概念に集中できるよう手順を簡略化します。

このレッスンでは、次のことを行います。

- GitHub Issue から新しいエージェントセッションを開始します。
- **Plan** モードで要件を定義します。
- **Autopilot** モードで新機能を実装します。
- コードをレビューします。
- ブラウザーキャンバスで機能を手動検証します。

この機能の作業を続けながら、リポジトリの指示を更新し、既存の `quality-checks` スキルをカスタマイズし、MCP による検証を追加して QA エージェントを作成し、機能の PR を開きます。

## シナリオ

Tailspin Toys のカタログが充実し、訪問者がカテゴリーとパブリッシャーでゲームを絞り込める機能が必要になりました。バックログの Issue に機能は記載されていますが、複数カテゴリーを組み合わせる方法などは、コーディング前に合意が必要です。Plan モードで決定事項を整理してから、Autopilot による範囲を限定した実装を承認します。

## 背景

AI コーディングエージェントを開発フローに導入しても、基本は変わりません。むしろ、基本はさらに重要になります。多くの開発者は、次のようなフローに従います。

1. 必要な作業の詳細が記載された Issue を開きます。
2. 構築する内容の計画を立てます。
3. コードを実装してレビューします。
4. テストを実行してコードを検証します。
5. 新機能を手動で検証します。
6. pull request (PR) を作成します。
7. コードのレビューと継続的インテグレーションが成功したら、コードをマージします。

> [!NOTE]
> 詳細な手順はチームや Organization によって異なりますが、多くの場合は上記の流れを調整したものです。

この標準的なアプローチに従うことで、AI が生成したコードが定められた要件を満たし、人が作成したコードと同じレビューのプロセスを通るようにできます。

## セッションモード

**セッションモード**は、エージェントにどの程度の自律性を与えるかを制御します。プロンプトフィールドの下にあるドロップダウンから設定し、いつでも変更できます。

- **Interactive**: エージェントと一緒に作業します。エージェントは変更を提案し、続行する前に入力を待ちます。
- **Plan**: エージェントが最初に計画を作成します。計画の実行前に内容をレビューして承認します。
- **Autopilot**: エージェントは完全に自律して作業し、入力を待たずにコード作成、テスト、反復を行います。

Plan モードで開始して計画をレビューし、その後 Autopilot で実装します。

## Issue からセッションを開始する

開始前に、星評価の PR がマージされ、ローカルの `main` が最新であることを確認します。

1. サイドバーの **Sessions** で Tailspin Toys のリポジトリフォルダーを選択し、リポジトリの上部ナビゲーションにある **Issues** を選択します。**Allow users to filter games by category and publisher** を開きます。これはテンプレートに含まれる Issue なので、新しく作成する必要はありません。
2. **New session** を選択し、更新済みの `main` に基づく **new working tree** を選びます。

    ![GitHub Copilot app の Issue ビューで New session ボタンを矢印で示した画面](../../../_images/app-new-session-from-issue.png)

3. Issue がセッションに添付されていることを確認し、モードセレクターで **Plan** を選びます。

> [!NOTE]
> Node.js または npm が見つからない場合は、エージェントに `node --version` と `npm --version` を実行するよう依頼します。ターミナルでは動作するのにセッションで見つからない場合は、アプリの PATH またはバージョンマネージャーの設定を確認し、アプリを完全に終了してから再起動します。失敗した操作とチェックを再試行してください。エージェントが npm を見つけられないという理由だけで npm を再インストールする必要はありません。

## フィルター機能を計画する

計画を立てると、Copilot がコードを書く前にアプローチをレビューできます。Issue から開始したため、Copilot は機能のリクエストをすでにコンテキストとして把握しています。次を送信します。

```plaintext
Build this feature.
```

Copilot の質問に回答し、Issue の受け入れ条件と計画を照らし合わせます。カテゴリーとパブリッシャーによる絞り込み、アクセシブルなコントロール、データアクセスの変更、テストが含まれていることを確認します。複数カテゴリーの組み合わせ方や、一致するゲームがない場合の動作など、不明確な点を話し合います。

計画には、プロジェクトの既存ツールを使った lint、単体テスト、E2E テスト、型チェックを含めます。フィルター機能の実装とテストに範囲を絞ります。品質ワークフローが完了してから PR を作成します。計画の修正は承認前に依頼し、後で検証できるよう Issue の URL と合意した追加の取り決めを控えておきます。

## Autopilot を明示的に承認する

計画に納得したら、**Approve and implement this plan**、または使用中のバージョンに表示される同等のオプションを選択します。承認によってモードが自動的に切り替わるとは限らないため、現在のモードを確認してください。モード表示が **Autopilot** になっていることを確認します。

Copilot が実装を開始します。計画に沿って作業し、コードを生成してテストを実行しながら、処理を反復します。

> [!NOTE]
> 承認すると実装がすぐに始まる場合があるため、先に計画をレビューしてください。依存関係不足やポート競合が報告された場合は、チェック完了と判断する前にセットアップの問題を解決します。停止してよいのは、自分で起動したサーバーだけです。

## 実装をレビューして検証する

生成されたコードも、他のコードと同じようにマージ前にレビューします。コードを確認し、サイトを実行して問題がないことを確かめましょう。

1. **Changes** を開き、フィルター機能の実装とテストを確認します。
2. 複数カテゴリーとパブリッシャーの組み合わせも含め、結果を Issue と合意した内容に照らし合わせます。変更が既存のリポジトリの指示に従っていることも確認します。
3. lint、単体テスト、E2E テスト、型チェックの結果を確認します。スキップされたチェックは成功ではありません。
4. 実装を承認する前に失敗を解消し、該当するチェックを再実行します。Playwright の E2E 設定はビルドしてプレビューを配信し、ローカルサーバーを再利用できます。以前のレッスンではなく、この worktree のサーバーがテスト対象であることを確認します。

## 新機能を確認する

コードに問題がないように見えても、実際に動くか確認しましょう。前と同じようにアプリを起動し、ブラウザーキャンバスでサイトを開きます。

1. 次のプロンプトを使い、アプリを起動してブラウザーキャンバスでページを開くよう Copilot に依頼します。

    ```plaintext
    Start the app and open it in the browser canvas.
    ```

2. しばらくするとアプリが起動し、Copilot app 内にブラウザーウィンドウが開きます。
3. カテゴリーを選択し、結果が一致することを確認します。フィルターを解除してからパブリッシャーを選択し、結果がそのパブリッシャーに一致することを確認します。
4. カテゴリーとパブリッシャーのフィルターを組み合わせ、結果を Issue と承認済みの計画に照らし合わせます。複数カテゴリーがサポートされている場合は、合意した組み合わせ方も検証します。
5. 該当するゲームがない組み合わせを試し、空の状態を確認します。フィルターを解除またはリセットし、全ゲームの一覧に戻ることも確認します。
6. 確認が終わったら、次のプロンプトを使って、このセッションで起動した開発サーバーを停止するよう Copilot に依頼します。

    ```plaintext
    Stop the dev server and close the browser canvas.
    ```

## 次のレッスンのためにセッションを維持する

フィルター機能の PR は、まだ作成またはマージしないでください。レッスン 4 から 8 まで、このセッション、worktree、ブランチを維持します。次のレッスンではカスタム指示をフィルター機能のコードに適用し、その後スキルと QA の改善を追加してから、レッスン 8 で関連する PR を作成してマージします。開発サーバーを停止した後、セッションをアイドル状態にしてもかまいません。次のレッスンでは同じセッションに戻ります。
